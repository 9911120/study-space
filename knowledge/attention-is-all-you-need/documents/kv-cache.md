# KV 캐시 — 문맥의 계산 결과 보관

인과적 어텐션에서는 과거 위치의 표현을 계산할 때 미래 토큰을 참고하지 않습니다. 같은 문맥을 이어 생성한다면 과거 위치의 K와 V를 다시 사용할 수 있습니다. 새 토큰의 Query는 이 저장된 값들을 참고합니다.

## 왜 Q는 같은 방식으로 보관하지 않나요?

새 토큰의 출력을 만들 때 필요한 Query는 새 위치의 것입니다. 과거 Query가 과거 문맥을 조회한 결과를 다시 모두 계산할 필요가 없으므로, 기본적인 캐시의 중심은 K와 V입니다.

## 메모리를 직접 추정합니다

K와 V의 폭이 같은 단순한 경우, 다음 식으로 대략적인 저장량을 계산할 수 있습니다.

```text
2 × 층 수 × 배치 크기 × 저장 토큰 수 × KV 헤드 수 × 헤드 폭 × 원소 바이트
```

가상의 설정이 32층, 배치 1, 4,096토큰, KV 헤드 8개, 폭 128, 원소당 2바이트라면 약 **512 MiB**입니다. 모델 가중치·기타 활성값·할당 여유분은 제외한 K·V 자체의 계산입니다. 실제 엔진의 할당량과 다를 수 있습니다.

## 현대 구조에서는 헤드 수를 확인합니다

일반적인 MHA와 달리 GQA나 MQA는 Query 헤드 수와 KV 헤드 수가 다를 수 있습니다. 따라서 Query 헤드 수를 그대로 위 식에 넣으면 잘못 추정할 수 있습니다. 이것은 원문의 기본 구조 이후에 발전한 설계입니다.
