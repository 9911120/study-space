# 05 · 오늘의 추론과 서빙으로 연결합니다

이 그룹은 **2017년 논문 이후의 실행 개념**을 설명합니다. 프리필·KV 캐시·서빙 지표를 원문의 새 발명이라고 주장하는 부분이 아닙니다. 원문에서 배운 어텐션과 자기회귀 생성을 현재의 서비스 경험에 연결하는 확장 학습입니다.

## 한 요청의 실행을 나눕니다

1. 문자열을 토큰화하고 모델이 기대하는 입력 형식으로 만듭니다.
2. **프리필(prefill)**에서 주어진 프롬프트를 처리합니다.
3. **디코드(decode)**에서 새 토큰을 하나씩 선택하며 이어갑니다.
4. 종료 조건이 충족되면 결과를 마칩니다.

이 그룹의 주된 대상은 인과적 디코더 전용 모델입니다. 원문 번역 모델에는 별도의 인코더와 cross-attention 경로가 있으므로 캐시 대상과 실행 경로도 그대로 같지는 않습니다.

## API 경험에 대응시킵니다

첫 글자가 나올 때까지 오래 기다리는 것과, 글자가 나온 뒤 이어지는 속도가 느린 것은 다른 현상일 수 있습니다. 전자는 입력 처리 외에도 대기열과 네트워크 등의 영향을 받고, 후자는 토큰 반복 계산과 서빙 정책 등의 영향을 받습니다.

## 저장되는 상태도 구분합니다

가중치는 모델이 학습한 값이고, KV 캐시는 이번 문맥의 중간 계산 결과이며, 앱의 대화 기록은 별도의 데이터입니다. 이 셋을 모두 ‘모델의 기억’이라고 부르면 원인을 찾기 어려워집니다.
