# 01 · 왜 Transformer가 필요했을까요?

이 지도는 **Applied AI 엔지니어가 모델 내부의 계산을 처음 배우는 상황**을 가정합니다. API 호출·배열·행렬의 기본 감각은 활용하되, 학습과 추론의 차이나 신경망 용어는 처음부터 설명합니다.

## 논문의 질문부터 잡습니다

2017년 Vaswani 등의 연구는 “번역 모델에서 반복적인 순환 계산을 빼고도 문장 사이의 관계를 잘 처리할 수 있는가”를 다룹니다. Transformer라는 모델 구조를 제안하고 번역 실험으로 평가합니다. 어텐션 자체를 처음 발명한 논문은 아닙니다.

원문은 **번역용 인코더·디코더 모델**입니다. 오늘날 사용하는 대화형 LLM을 그대로 설명하는 설계서로 읽으면, cross-attention이나 학습 데이터에서 혼란이 생깁니다.

## 이 지도에서 공부하는 순서

1. 이 그룹에서 RNN → 인코더·디코더 → 기존 어텐션 → Transformer의 문제의식을 파악합니다.
2. 아래 02에서는 원문 번역 모델의 입력과 출력을 따라갑니다.
3. 오른쪽 03에서는 어텐션 수식을 작은 숫자로 계산합니다.
4. 04와 05에서는 학습의 병렬 처리와 추론의 순차 생성을 구별합니다.
5. 06에서는 실험이 입증한 범위와 오늘의 모델·서비스에 남은 영향을 정리합니다.

좌우 화살표는 역사적 진행이나 실제 계산 순서입니다. 아래로 내려가는 연결은 해당 개념의 세부 설명입니다. 그룹 번호는 권장 읽기 순서이며, 모르는 개념으로 이동했다가 돌아와도 됩니다.

## 이번 공부의 도착점

논문 수식을 외우는 것보다 “어떤 배열을 받아 어떤 배열을 만들며, 왜 그 계산이 필요한가”를 설명하는 것을 목표로 합니다. 이후에는 긴 프롬프트의 비용, KV 캐시, 첫 토큰 지연 같은 서비스 현상도 모델 계산과 연결할 수 있게 됩니다.
