# 토큰에서 입력 벡터로

웹 API에 보내는 문자열이 신경망의 행렬 계산에 바로 들어가는 것은 아닙니다. 먼저 **토크나이저**가 텍스트를 조각으로 나누고 어휘 표의 ID로 바꿉니다. 단어 수와 토큰 수는 같지 않을 수 있습니다.

```text
문자열 → 토큰 ID 목록 → 임베딩 조회 → 위치 신호 결합
```

## 임베딩은 학습 가능한 표입니다

어휘 수가 V이고 벡터 길이가 d라면, 임베딩 표의 크기는 `[V, d]`입니다. ID 17을 받으면 17번 행의 숫자들을 꺼냅니다. ID의 숫자 크기에 의미의 순서가 있는 것은 아닙니다.

길이 4인 입력을 폭 8의 벡터로 바꾼다고 가정하면 결과는 `[4, 8]` 배열입니다. 여기서 4는 토큰 위치 수이고 8은 각 위치의 특징 수입니다. 이 수치는 배열 모양을 설명하기 위한 작은 예시입니다.

## 처음 표현과 문맥 표현은 다릅니다

같은 토큰 ID는 같은 시작 벡터를 꺼낼 수 있습니다. 하지만 뒤의 블록에서 다른 토큰과 정보를 주고받으면 문맥에 따른 표현으로 바뀝니다. “배를 먹는다”와 “배를 탄다”에서 같은 조각이 등장해도 이후 표현은 달라질 수 있습니다.

이때의 토큰 임베딩을 벡터 검색에 쓰는 문장 임베딩 API와 바로 동일시하면 안 됩니다. 문장 전체를 어떻게 모아 표현하는지는 별도의 모델·학습·풀링 설계에 달려 있습니다.

## 확인합니다
