# 내 앱에서 무엇을 판단할까요?

이 문서는 앞에서 배운 개념을 앱 개발에 연결하는 학습 제안입니다. 특정 모델이나 서비스에 대한 성능 보장은 아닙니다.

## 현상을 계산의 위치로 옮깁니다

| 앱에서 하는 일 | 모델 관점에서 먼저 확인할 것 |
| --- | --- |
| 검색 문서를 프롬프트에 넣습니다. | 입력 토큰 수와 내용이 바뀝니다. 검색 자체는 모델 바깥일 수 있습니다. |
| 미세 조정을 수행합니다. | 학습 절차로 일부 또는 전체 가중치를 갱신합니다. |
| temperature를 바꿉니다. | 주로 출력 후보를 선택하는 분포가 달라집니다. |
| KV 캐시를 사용합니다. | 앞 문맥에서 만든 중간 계산을 재사용합니다. |

## 지연 시간을 나눠 봅니다

첫 토큰까지의 시간(TTFT), 이후 토큰 사이의 시간, 전체 완료 시간은 구별합니다. 서비스의 TTFT에는 대기와 전송도 들어갈 수 있으므로 프리필 시간과 무조건 같지는 않습니다. 지표의 정확한 측정 시작·종료 지점은 엔진 문서를 확인합니다.

## 작은 실험을 설계합니다

같은 과제와 비슷한 출력 길이를 유지하면서 입력 길이만 바꿔 봅니다. 이어서 입력을 고정하고 출력 길이 제한을 바꿉니다. 캐시 유무나 동시 요청 수도 따로 바꿔 보면 한 번에 모든 조건을 바꾸는 것보다 원인을 읽기 쉽습니다. 정답률과 형식 준수도 함께 기록합니다.

## 다음 질문을 고릅니다

설명이 막히는 지점에 따라 “마스크를 직접 구현해 보기”, “KV 메모리 예측하기”, “현재 앱의 TTFT 분석하기”로 이어갈 수 있습니다. 지금은 모든 최적화를 외우기보다 어느 비용을 줄이려는지 질문할 수 있으면 됩니다.
