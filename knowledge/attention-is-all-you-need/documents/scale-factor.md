# 왜 √dₖ로 나누나요?

Query와 Key의 길이가 길어지면 내적에서 더하는 항의 수도 늘어납니다. 각 성분이 독립적이고 평균 0, 분산 1이라고 단순화해 가정하면, dₖ개 곱을 더한 내적의 분산은 dₖ가 됩니다.

## 표준편차에 맞춰 규모를 조정합니다

분산이 dₖ이면 표준편차는 √dₖ입니다. 내적을 √dₖ로 나누면 위 가정 아래에서 점수 규모가 차원 수에 덜 의존하게 됩니다. 실제 학습된 벡터가 항상 이 가정을 정확히 만족한다는 뜻은 아닙니다.

## Softmax와 연결됩니다

가상 점수 `[1, 0]`의 softmax는 약 `[0.731, 0.269]`입니다. 점수를 열 배로 키운 `[10, 0]`은 거의 `[1, 0]`이 됩니다. 너무 한쪽으로 몰리면 학습에 유용한 기울기 특성이 나빠질 수 있습니다.

스케일링은 이런 점수 규모를 다루는 설계입니다. 정확도를 일정하게 보장하거나 모든 학습 불안정을 해결하는 장치는 아닙니다.

## 생성 temperature와는 위치가 다릅니다

생성 temperature도 softmax에 들어가는 점수의 규모를 다루지만 보통 어휘 출력 분포의 선택 과정에서 등장합니다. 여기서는 블록 내부의 어텐션 점수를 다룹니다. 비슷한 수학적 모양을 갖더라도 적용하는 대상과 목적을 구별합니다.

## 확인합니다

dₖ가 토큰 개수인지 Key 벡터의 길이인지 답하고, 무엇의 제곱근으로 나누는지 설명해 보십시오.
